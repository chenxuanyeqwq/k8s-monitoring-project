## 阶段 1 · 放行安全组端口

ECS 用"安全组"控制端口(轻量服务器叫"防火墙")。

1. 阿里云控制台 → **云服务器 ECS** → **实例列表** → 点你的实例
2. 找到 **安全组** → **配置规则** → **入方向**
3. 放行以下端口(没有就"手动添加"):

| 端口 | 用途 |
|------|------|
| 22 | SSH 登录(一般默认已开) |
| 80 | HTTP → 301 跳 HTTPS / Let's Encrypt 验证(**必开**) |
| 443 | HTTPS 主入口(**必开**) |
| 8080 | 留言板旧入口(过渡保留,v3.6 后可关) |

验证:端口开好后,你的电脑浏览器能打开(暂时 404 也正常,服务还没起)。

## 阶段 2 · SSH 登录 + 检查环境

在你电脑的 **PowerShell** 里:

```powershell
ssh root@8.217.195.115
```

- 首次提示 `yes/no` → 输 `yes`
- 输 root 密码(不显示,正常)
- 登录成功会看到 `root@xxx:~#`

进去后逐条检查(把结果发给 Claude 确认):

```bash
cat /etc/os-release | grep PRETTY_NAME     # 系统版本
docker --version                            # Docker 装好没
docker compose version                      # compose 插件有没
```

> 如果 `docker` 报 command not found → 执行:`curl -fsSL https://get.docker.com | sh` 再装
> 如果 `docker compose` 报 command not found → 执行:`apt install -y docker-compose-plugin`

## 阶段 3 · 首次手动部署(先跑通,再谈自动化)

**3.1 在服务器上建目录**

```bash
mkdir -p /opt/k8s-project
```

**3.2 把 01-lnmp 传上服务器**

在你本地 PowerShell(不要登录服务器)执行:

```powershell
scp -r E:\dev\k8s-project\01-lnmp root@8.217.195.115:/opt/k8s-project/
```

**3.3 在服务器上拉取镜像 + 启动（阶段2：构建在 CI，服务器只拉）**

回到 SSH 会话:

```bash
cd /opt/k8s-project/01-lnmp
bash deploy.sh
```

> deploy.sh 从阿里云 ACR 拉取 php 镜像再起容器（**不再在服务器上 docker build**）。本机已保存 ACR 凭据会自动复用；否则先 export `ACR_REGISTRY/ACR_USERNAME/ACR_PASSWORD`。

**3.4 验证公网访问**

在你电脑浏览器打开:

```
https://www.fchen.xyz       ← 主入口（v3.6 起全站 HTTPS）
http://www.fchen.xyz        ← 自动 301 跳转 HTTPS
```

看到留言板页面 = 公网部署成功 🎉

> 打不开就检查:①安全组 8080 开了没 ②服务器上 `docker compose ps` 是不是 3 个 Running ③`docker compose logs --tail 30` 看报错。

## 阶段 4 · 推送代码到 GitHub

> 前提:注册一个 GitHub 账号。`.env` 已被 gitignore,不会把飞书 webhook 泄漏上去。

**4.1 在 GitHub 网页建仓库**(推荐**Private** 私有,名字随意如 `k8s-project`)

**4.2 本地关联并推送**(在你本地 PowerShell,项目目录 `E:\dev\k8s-project`):

```powershell
git add .
git commit -m "init: LNMP + 部署流水线"
git branch -M main
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

> 如果报错说没有 git 用户名/邮箱,先执行:
> `git config --global user.email "你的邮箱"` 和 `git config --global user.name "你的名字"`

推送成功后,到 GitHub 网页确认文件都上去了。

## 阶段 5 · 配置 GitHub Secrets

流水线要登录你的服务器,密码必须藏在 GitHub 的"保险箱"里,不能写进代码。

1. GitHub 仓库页面 → **Settings** → 左侧 **Secrets and variables** → **Actions**
2. 点 **New repository secret**,添加 3 个:

| Secret 名 | 填什么 | 例子 |
|-----------|--------|------|
| `SERVER_HOST` | 服务器公网 IP | `8.217.195.115` |
| `SERVER_USER` | SSH 用户名 | `root` |
| `SERVER_PASSWORD` | SSH 密码(root 密码) | `你设的密码` |

## 阶段 6 · 触发流水线(自动部署!)

**方式一(推荐):改代码自动触发**

在你的留言板代码里随便加一句(比如改 `01-lnmp/php/www/index.php` 的标题),然后:

```powershell
git add .
git commit -m "test: 触发自动部署"
git push
```

→ GitHub 自动检测到 `01-lnmp/**` 变了 → 自动跑流水线 → 30~60 秒后自动上线。

**方式二:手动触发**

GitHub 仓库 → **Actions** → 左侧点 **Deploy to Aliyun ECS** → 右侧 **Run workflow** → 绿色按钮。

**怎么看结果:**

1. GitHub 仓库 → **Actions** 标签 → 点最近一次运行
2. 看到 4 个步骤(Checkout / CI构建推送ACR / 上传 / 部署)全绿 = 成功
3. 绿的日志里能看到 `✅ 部署完成: https://www.fchen.xyz (镜像 tag: ...)`

**验证:** 浏览器刷新 `https://www.fchen.xyz`,能看到你改动的效果。

**回滚(阶段2):** 线上出问题时,在服务器上一条命令回到旧版本:

```bash
cd /opt/k8s-project/01-lnmp
bash rollback.sh <上次正常的commit完整sha>
```

会从 ACR 拉取对应版本的镜像并重启,自检通过后回到旧版。查看可用版本:`docker images | grep lnmp-php`。

## 阶段 7 · 黑盒监控接入公网

把 `06-blackbox/service_probe.py` 的探测目标从 localhost 改成公网 IP,让黑盒从"外网视角"盯你的服务器:

编辑 `06-blackbox/service_probe.py` 的 `TARGETS`:

```python
TARGETS = [
    {"name": "LNMP留言板", "url": "https://www.fchen.xyz", "headers": {}},
]
```

在**服务器上**配定时任务(每 5 分钟探一次,失败推飞书),或在你本地配 Windows 任务计划:

```bash
# 服务器上(需要先上传 06-blackbox,并把 .env 的 FEISHU_WEBHOOK 配上)
crontab -e
# 加一行:
*/5 * * * * cd /opt/k8s-project/06-blackbox && python3 service_probe.py >> /var/log/service_probe.log 2>&1
```

## 常见问题速查

| 症状 | 原因 | 解决 |
|------|------|------|
| 浏览器打不开 8080 | 安全组没放行 | 控制台安全组放行 8080 |
| https 打不开 | 安全组 80/443 没放行 | 控制台安全组放行 80/443 |
| 证书快过期 | Let's Encrypt 90 天有效期 | acme.sh 已自动续期 + 续期后自动 reload nginx,无需手动 |
| 部署脚本报 `fchen/lnmp-php` 拉取失败 | ACR 凭据不对或仓库不存在 | 核对 ACR_REGISTRY 域名、ACR_USERNAME/PASSWORD、命名空间 `fchen`/仓库 `lnmp-php` 是否存在 |
| 流水线红 X 在"CI构建推送"步 | ACR 登录/权限问题 | 检查 ACR 三个 Secret；docker login 报 401=用户名/密码错，报 denied=命名空间/仓库名错 |
| 流水线红 X 在"上传"步 | Secrets 没配对 | 检查 SERVER_HOST/USER/PASSWORD |
| 流水线红 X 在"部署"步 | 服务器 docker 权限或 ACR 拉取失败 | 看日志；服务器已保存的 ACR 凭据失效时重跑 deploy.sh 重新登录 |
| MySQL 中文乱码 | init.sql 编码 | 已在 compose 里配 utf8mb4,一般不会再出现 |
